# 11 — Risk Register

| # | Risk | Likelihood | Impact | Mitigation | Owner |
|---|---|---|---|---|---|
| 1 | Meta Ads Library has no stable scraping contract; DOM/selectors change without notice | High | High (collector breaks silently or noisily) | `collector:inspect` mandatory before writing selectors ([10](10-playwright-boundary.md)); Normalizer isolates the rest of the app from raw DOM shape; expect and budget for periodic selector maintenance | Collector implementer |
| 2 | LLM structured-output reliability varies by provider/model; a response may not parse against `DiscoveryPlanV1` | Medium | Medium (blocks plan generation) | App-side JSON Schema validation is mandatory before persistence; **at most one** repair attempt (Auto-fixing Output Parser or app-side re-call); hard failure surfaced to user otherwise — never a silently coerced/partial plan ([06](06-discovery-plan-contract.md)) | App + n8n workflow author |
| 3 | "Traction signal" vocabulary discipline erodes over time (a future contributor adds "confirmed sale" language to a prompt, schema field, or UI copy) | Medium | High (undermines the product's core integrity claim) | Vocabulary rule stated explicitly in [01-product-model.md](01-product-model.md); schema has no field capable of expressing a sales/ROAS claim by construction; recommend a lightweight copy-review checklist item in PR review | All contributors |
| 4 | Community Edition n8n has no Git-based Source Control (paid-only feature); naive assumption of Git-based workflow sync would silently not work | Low (now that it's verified) | Medium (would have caused an implementation surprise) | Confirmed via n8n's official edition-comparison docs; this repo standardizes on plain JSON export/import (`n8n export:workflow` / editor **Download**/**Import from File**) instead ([08](08-n8n-workflows.md), `n8n/README.md`) | n8n operator |
| 5 | n8n's pinned Docker image tag drifts out of date or a future minor version introduces a breaking change | Medium | Low–Medium (upgrade friction, not data loss, since `n8n_data` volume persists) | Pin an explicit version tag in `docker-compose.n8n.yml` rather than `latest`; document the manual `docker compose pull && docker compose down && docker compose up -d` update procedure; re-verify docs before bumping major versions | n8n operator |
| 6 | Loss of the `n8n_data` volume also loses n8n's auto-generated encryption key, making any separately-backed-up n8n SQLite/credentials undecryptable | Low | Medium (n8n credentials — the LLM API key — must be re-entered; no Market Demand Radar application data is affected, since none of it lives in that volume) | Accepted trade-off for local MVP simplicity: n8n manages its own key, no `.env.n8n` key-generation step required ([09](09-security.md), ADR-07 supersession in [14](14-decisions.md)); re-entering one LLM credential takes under a minute | n8n operator |
| 7 | Prompt injection via future scraped ad/landing-page content feeding an LLM step | Low today (no scraped content flows into prompts yet); rises once collector ships | Medium–High | Documented now as a forward-looking design note ([09-security.md](09-security.md)): treat scraped text as untrusted data, never instructions; avoid AI Agent tool-calling over untrusted content without explicit review | Collector + prompt author, when that phase starts |
| 8 | Webhook exposed without any authentication once n8n moves to a VPS (public internet reachable) | Medium (if migration is done carelessly) | High (arbitrary LLM spend, potential data exposure via crafted requests) | Explicit **FUTURE WORK** flag on the VPS switch itself ([04](04-future-vps-switch.md), [09](09-security.md)) — the switch must not proceed without first designing app↔n8n authentication; local MVP intentionally ships with none since loopback binding already makes the webhook unreachable from outside the machine | Whoever performs the VPS switch |
| 9 | Overlapping/duplicate LLM generations or manual revisions from accidental double-submit (e.g. user double-clicks "Generate"), or a frontend retry after a dropped connection | Medium | Low–Medium (wasted LLM spend, extra plan versions to clean up) | `requestId` + `RequestLog` unique-constraint idempotency ([05](05-data-model.md), [07](07-api-contract.md)) makes a repeated request return the existing result instead of creating a duplicate version or re-calling n8n, regardless of frontend behavior; no app-level automatic retries either | App implementer |
| 10 | SQLite is a poor fit if usage patterns change (concurrent writers, multi-machine access) | Low for MVP | Medium if it happens | Explicitly out of scope for now; documented as a "Postgres would need strong justification" decision in [14-decisions.md](14-decisions.md) — revisit only if a concrete concurrency need materializes | Future maintainer |
| 11 | Destructive Data Explorer actions (delete project/record) executed accidentally | Low | Medium (research data loss) | Mandatory `{ "confirm": true }` body on all destructive `/api/data/*` calls, never a bare link-triggerable delete ([07](07-api-contract.md), [09](09-security.md)) | App implementer |
| 12 | Playwright collector runs away (excessive requests, long runtime, gets the user's IP flagged/blocked) | Medium once built | Medium–High | `discoveryLimits` (`maxQueriesPerRun`, `maxAdsPerQuery`, `maxScrollsPerQuery`, `stopAfterScrollsWithoutNewAds`, `maxRuntimeMinutes`) + `saturationCriteria` enforced by the scheduler as hard stops, not advisory logging; user-triggered stop must actually halt navigation ([10](10-playwright-boundary.md)) | Collector implementer, when that phase starts |
| 13 | LLM proposes a `discoveryStrategies[]` entry the collector cannot actually execute | Low | Medium (plan looks actionable but isn't) | `source`/`mode` are constrained enums matched to `availableDiscoveryCapabilities` sent in the MR-01/MR-02 request; the schema structurally cannot express a non-executable strategy today ([06](06-discovery-plan-contract.md), [07](07-api-contract.md)) | n8n workflow/prompt author |
| 14 | Manual plan edits (frontend bug or user error) introduce duplicate/malformed item `id`s | Low | Low–Medium (broken UI keys, ambiguous stable-ID history) | Same schema + stable-ID structural validation runs for manual revisions as for MR-02 output before persistence; invalid edits are rejected, not silently coerced ([06](06-discovery-plan-contract.md), [07](07-api-contract.md)) | App implementer |
